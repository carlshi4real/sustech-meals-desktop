# 南科饭钱 · Mac 桌面版

面向 macOS 13 及以上、Apple Silicon（M 系列芯片）Mac 的本地应用。当前先交付 Mac 版，同一套 Electron 源码可继续适配 Windows，但此次尚未生成 Windows 安装包。

## 使用

解压「南科饭钱-Mac.zip」后，打开「南科饭钱.app」。应用已内置运行环境，无需 Node.js 或 Expo。可将 .app 放入“应用程序”文件夹。

本版本使用本地临时签名，未经过 Apple Developer ID 签名和公证，系统可能对首次打开作出限制；它不是已经上架的 Mac App Store 软件。

1. 打开“预算计划”，填写计划开始日期、该日可用于餐饮的资金、期间餐饮预算、截止日和完整记账起始日。
2. 打开“校园卡导入”，点击“打开学校网站并登录”。学校官方窗口支持账号或页面提供的扫码方式。
3. 登录后返回应用，点击“一键同步账单”。应用自动逐页读取。
4. 同步完成后，在“消费账单”中核对每条记录的“餐饮”勾选。
5. 概览自动生成每日餐费、常去地点、可维持天数及每日可用额度。

## 校园卡一键同步

用户在学校官方页面手动输入自己的账号密码；应用不内置测试凭据，也不读取或保存密码。登录后点击“一键同步账单”，应用验证账户、自动打开交易记录、逐页读取消费与退款，并按交易号去重。一次最多读取 200 页，超过限制会提示；分页失败、登录过期或解析异常时不会写入不完整数据。

已依据真实网站“创建时间 / 名称与交易号 / 对方 / 金额 / 付款方式 / 状态”列适配。只导入“交易成功”的消费与退款，充值、转账、圈存和补助不会计入餐费。食堂、餐厅和大众窗口默认标为餐饮；小卖部和未知商户默认不计入餐饮，可以在账单页手动调整。

首次同步会将本地账本绑定到该校园卡账户的散列标识，防止其他账户的账单混入。原始账号和密码不会随应用交付。账本在用户电脑上单独保存，安装包不包含测试账单。

已完成真实网站同步验证：读取 18 页，共 174 条消费或退款记录；再次同步新增 0 笔，跳过 174 笔重复记录。网站结构未来变化时可能需要更新适配。同步由用户点击启动，不是应用退出后仍运行的后台任务。

## 计算口径

- 实际餐费：仅计算标为“餐饮”的记录，退款抵减支出。
- 餐饮余额：计划开始时可用资金 − 计划开始日起的已记餐费。
- 餐饮日均：完整记账起始日至今天的净餐费 ÷ 自然日数，零消费日也计入分母。
- 预计还能吃多少天：餐饮余额 ÷ 餐饮日均，向下取整。没有有效日均时不显示无限天数。
- 每日可用额度：max(min(餐饮余额, 剩余餐饮预算), 0) ÷ 到截止日的剩余天数，包含今天。
- 预计结余/缺口：min(餐饮余额, 剩余餐饮预算) − 餐饮日均 × 剩余天数。

“还能吃多少天”仅指餐饮，不包含房租、交通、购物，也不是对全部生活资金的保证。今日尚未结束，预测按还需要一天餐费保守估算。漏记会造成日均偏低。资金输入应使用计划开始时的余额，不要再重复扣除计划内已记账单。

## 数据

账本只保存在本机用户数据目录的 ledger.json。应用提供备份和恢复；恢复会询问是否替换当前账本。该账本与之前手机版分别保存，备份格式也不同。

学校页面禁用 Node.js，启用沙盒和上下文隔离。只允许官方校园卡和统一认证域名作为主窗口页面；应用不读取密码或保存校园密码，学校会话仅保留在当前运行期间。若学校认证后来需要其他域名，应先核实再适配。

## 开发与验证

```sh
npm ci
npm test
npm run package:mac
```

首次打包会下载 Electron 官方运行时。打包脚本将缓存和产物放在项目上两级目录的 work/ 下。

已通过 10 项计算和导入逻辑测试，并在本机实际打开 Mac 应用、登录官方学校网站。Windows 运行尚未验证。

## 消费账单视图

“消费流水”显示每笔账单；“按消费地点”按净支出从高到低汇总消费次数、消费总额、退款总额、净支出和平均每次金额。统计包含非餐饮账单，并响应地点或日期搜索。点击“查看流水”可核对某个地点的记录，点击“查看全部地点”取消地点筛选。
